# Game menu audit (analyst findings, plain language).

1. DIFFERENT M — Victory: turn-based: check runs as each game turn wraps, sets a "completed" flag. Game goes on for ONE full game turn: every computer player plays; every human gets usual sign-in, then the Victory ending (saying this is the last turn and pointing to the Scores window), then plays that turn normally. At the next wrap, before any event or turn processing, OK box "Game Completed" says the game is over, program exits. Ours resume() loops while(!s.gameOver) (src/game/turn_based.cpp ~494) so no player turn starts after victory; applyLive refuses "The game is over."; endPlayerTurn nothing; human sees Victory window then stuck in frozen game. Spec 05 §6, spec 06 §1.9.
2. DIFFERENT M — Order failures in turn-based games while the human whose turn it is carries them out: a titled OK box at once. Confirmed for Move (a vehicle that is building items cannot move) and Colonize. Same two-way code exists (inferred) for "Damage Taken" (moving through a damaging sector), Drop Cargo, Launch Warning, Recover Warning, Cannot Mothball, retrofit, stellar-manipulation "Cannot ..." boxes, Minefield, Drop Troops. Simultaneous: same failure becomes matching minister's log entry (e.g. "Unable to Move" from Fleet Minister). Ours fail() movement.cpp:736 writes Misc log line "<name>: <order> order cancelled" in both styles; only Colonize gives a box. Spec 03 §8 general reporting rule.
3. DIFFERENT M — Any close of main game window (title-bar close, Alt+F4, Game Menu Quit) asks a quit confirmation naming the game Yes/No; skipped only while a turn is processed. Ours only Game Menu Quit asks; app.cpp:396-397 stops at once. Spec 06 §4.3.
4. MISSING L–M — Progress window: small modal with centred caption and dark-blue 0–100 gauge: a turn-processing caption while a simultaneous turn processed on the host (hidden when headless; work split into (number of empires x 4 + 30) steps); a galaxy-creation caption and a player-placement caption when a new game starts. Ours hourglass only. Spec 06 §1.7/§2.7.
5. DIFFERENT L — Endings: each ends the turn loop and program exits: No to the question whether to keep playing after conquest; Human Dead ending; "Game Completed"; fourth wrong password in Next Player; Yes to turn-based different-machines "shut down now?" (No -> intro). Ours conquest-No -> intro (finale_screen.cpp:126); after Human Dead stays in game where End Turn does nothing. Returning to intro is a reasonable stand-in for exiting, apply consistently incl after Human Dead. Spec 06 §1.9 / Q99.
6. DIFFERENT L — Human loses everything during its own turn (Q99(a)): no destruction check for a human at end of its own turn; alive when computers move. At its next turn start, in order: Next Player sign-in (if >1 human), autosave if due, Lose ending, turn-start processing (carried-over orders, ministers, log). Then destroyed at once: others told, treaties end, dead mark set. Then plays that "last turn" already marked dead. Ours finishPlayerTurn calls score::checkDestruction for humans -> dies at end of own turn with no Lose window; normal case marked dead at end of last turn, not start. Spec's "marked dead ... at the end of that last turn" (§1.9, Q83) inaccurate.
7. DIFFERENT L — Game Menu New ("Cancel Game") asks whether to cancel and start a new one; Yes discards game and opens 8-page Game Setup at once over blank backdrop with star-map picture; Begin Game starts new game; Cancel -> intro. Ours asks then returns to title (game_menu.cpp:161).
8. DIFFERENT L — Load Game list opens sorted by save name A->Z (names in capitals); clicking "Save Game Name" or "Date" header re-sorts (dates newest first) with usual five-key sort history. Ours always newest first, no header sort (file_dialog.hpp listFiles). Header click likely.
9. COSMETIC/DIFFERENT L — Save Game: Load Game dialog titled "Save Game", listing saves name+date, buttons New Save Game, Change Directory, Cancel. Click existing save overwrites with no question. New Save Game asks "New Save Game Name"; invalid name -> "Invalid File Name." (title "Error"), asks again. Change Directory saves to another folder for that one save. Closes with no "saved" message. Delete Game deletes on click no question, also removes same-named file in temp/, closes. Ours own window with name box; our overwrite/delete confirmations are fine additions; no Change Directory in Save Game.
10. DIFFERENT L — Next Player: shown whenever more than one empire is human-controlled (dead ones included) at each human's turn (surviving hotseat player still sees it). 276x188 window, empire's picture and a line naming the empire and inviting its player. Password: leading/trailing spaces ignored, CASE COUNTS (simultaneous sign-in ignores case). Failures: label "Invalid Password:"; fourth wrong entry ends the program. Loading: autosave or hand-over file opens Next Player then that player's turn start; plain save asks nothing; every simultaneous game (single-player incl) asks "Login To Game" when loaded. Ours: hand-over only when active human changes; loaded game counts only living humans; passwords exact, unlimited tries; local simultaneous game asks no sign-in. Spec 06 §1.2.1 wrong for Next Player case.
11. MISSING L — Ministers Indiv. Ministers On/Off "Confirm" (= economy #13).
12. DIFFERENT L — Autosave written at start of the first human's turn of each new game turn when date is multiple of interval: after Next Player, before endings and turn-start processing; file marked as autosave. Ours after whole End Turn call (session.cpp:466).
13. COSMETIC L — Help -> Manual opens installed manual\SE4 Manual.htm in browser at once. Ours own Manual window; keep ours, add direct link alongside.
14. DIFFERENT L — Data-file errors at start-up: error-list window per data file ("<File> ... Errors: <path>" + Close). Ours refuses to start, first 15 errors. Whether original continues: inferred.
