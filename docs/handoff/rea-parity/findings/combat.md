# Combat windows audit (analyst findings, plain language).

1. MISSING M — Boarding outcome message boxes after Capture Ship: to attacker if human plays it by hand (Auto off), to defender if human plays that side by hand (Auto off); each side checked separately. Self-destruct (title "Self-Destruct"): target blew itself up during boarding, both ships gone; to attacker/defender/both if by hand. Success ("Ship Boarded"): hand-played attacker sees a line saying ship A boarded and took over ship B; if attacker computer-run and defender hand-played, defender sees a line saying ship B was boarded and taken over by ship A. Failure ("Boarding Failed"): a line saying ship A failed to board ship B to either side if by hand. Computer uses same code in its phases, so a human defender in Tactical is told. When every side automatic (Strategic, Auto, Resolve Combat), no boxes. Ours: no box; map changes owner + "C" mark (combat_map.cpp:263). Spec 04 §12, spec 06 §1.10.2 (spec 04 §15 only says human gets box on capture).
2. MISSING L–M — Laying mines in tactical combat: Launch Units window launches mines too; ship limit = its mine-laying rate per combat turn; planet limit 100 per combat turn if it holds mines; per-sector mine cap applies; mines join sector's minefield, not combat pieces. Ours refuses "Only fighters, satellites and drones are launched in combat." (src/game/combat_tactical.cpp:110). Spec 04 §10.5 implies; code gap; say plainly.
3. DIFFERENT L–M — Launch Units window in combat: L (or Orders menu) opens same "Launch / Recover Units" window as main map in battle mode. Amount: four radios Move One / Move Five / Move Ten / Move All, remembered per empire. Left list: only selected piece and its cargo units; under the piece "Can Launch:" and a line each for N Fighters, Satellites, Mines, Drones left this combat turn. Right list: only groups launched while this window has been open (empty at first); clicking one recovers it into the piece (undo before closing). In battle the fighters-need-full-movement-to-recover test skipped. Ours small window (tactical.cpp:1290), per-stack 1/5/10/All buttons, one sentence of counts; no recover, no remembered amount, no mines. Unknown whether recovery gives back launch capacity. Spec 06 §1.10.2, spec 04 §10.4.
4. DIFFERENT L–M — Ticked weapons are the window's state, not the piece's. Reset: every time a piece becomes selected (click, Space/Ctrl keys, start of each phase, after every move of the piece) ticks go to every intact weapon not reloading. After firing, weapons that fired are unticked. Shift+A ticks only intact ready weapons; Shift+C unticks all. Ours per-weapon on/off flag lasting battle (combat_battle.hpp:53); Shift+A turns on every weapon. Unknown: whether reloading weapon can be ticked by hand. Spec 04 §6, spec 06 §1.10.1.
5. DIFFERENT M — Next/previous piece (Space, Ctrl+N/B, Ctrl+F/D, title-strip buttons) searches up to three passes around the side's pieces, seekers and drones skipped, each pass starting after current piece: (1) group leaders that can move (or fire); (2) any piece that can move (or fire); (3) "move" kind only: the side's first planet. "Next" walks list in reverse, "previous" forward. At start of each hand-played phase selection made this way walking forward (first group leader incl fleet leaders with movement first). Ours plain cycling, phase start first piece that can move (tactical.cpp:188,441). Spec 06 §3.3, §1.10.1.
6. MISSING/DIFFERENT M — Target panel (screens >= 1024 wide): after each hit drawn while target panel shows a piece, a 220x20 line 66px below panel top: "Damage: " white, shield damage blue, "/" white, structure damage red; shot destroying target counts all its shields+structure. A piece fills panel only while pointer over a piece of another empire (allies incl) with one of ours selected; moving onto empty square, neutral piece, or into Ram/Capture aim clears; empty before Begin. Seeker impact puts struck piece in panel. Ours no damage line, panel keeps last enemy, window picks nearest enemy itself (tactical.cpp:445), allies never, seeker hits don't change panel. Spec 06 §1.10.1 / §7 Q97.
7. DIFFERENT L — Orders menu all 11 items always enabled. R/C keys set Ram/Capture aim even with nothing selected. Ram refusals (title "Ram Ship") in order: no source piece; target not found; not adjacent; no movement left; target not hostile ("you cannot ram your allies"). Capture refusals ("Capture Ship") in order: no source; no target; target unowned or not a ship ("cannot be captured"); source not a ship; our own ship; not adjacent; no boarding ability; target's shields up; not hostile (this last titled "Ram Ship" and shows even for computer side). Other Ram/Capture boxes only for hand-played side. Clicking a non-hostile piece (ally, own drone group) with a piece selected tries to fire -> "Cannot Fire Weapons" box (cannot fire on allies). Ours dims items (Ram w/o movement, Capture w/o boarding parties, tactical.cpp:1268-1269), engine wording as yellow map text, clicking ally selects it for viewing (tactical.cpp:732). Spec 06 §1.10.2.
8. DIFFERENT L — Ram target can be any adjacent piece not ours and not friendly, incl enemy seekers; unowned pieces (neutral obstacles) count as hostile. Ours refuses both (combat_tactical.cpp:192-194; hostileTo needs both owners valid). Spec 04 §10.3 already; code gap.
9. DIFFERENT L — Alt+N / Set Group Leader with the number the piece already leads reopens formation list and sets new formation. Member, or leader of another number, gets nothing (no list). Cancelling clears the piece's group marks. Ours refuses "It already belongs to a group." (combat_tactical.cpp:216), opens list for members/other leaders then refuses silently. Spec 04 §19 Q64 code gap; spec 06 §1.10.2.
10. DIFFERENT L — Before Begin: left-click on any piece (enemies incl) selects it into current-piece panel and weapon grid; empty squares nothing. E acts as Begin (presses fourth button whatever label). Auto enabled before Begin; only Orders dim. Ours ignores clicks/keys before Begin, Auto dim (tactical.cpp:636,1164,974-987). Spec 06 §1.10.1, §3.3.
11. DIFFERENT L — Center Map on Current Ship recentres only when newly selected piece's square is outside shown map part; with switch on, seeker's struck piece recentred same way. Ours always recentres (tactical.cpp:459). Spec 06 §1.10.3.
12. COSMETIC L — Show Group Identifiers on every piece with group number, any empire; 14x12 box at square's top right, blue leader, red member, number white centred. Ours only player's pieces, scaled square (tactical.cpp:579).
13. COSMETIC L — Weapon cells: teal background = ticked (not ready); up to 5 red 3x6 bars, one per combat turn of reload left, drawn leftward from x+32, 4px apart; hit chance right-aligned top right, ready weapons only; unit-group count top right when >1. Ours teal = ready, one red mark, hit chance middle, ready count bottom left (tactical.cpp:900-931). Spec 06 §7 Q97.
14. DIFFERENT L — Combat Simulator Begin refused only when no item has an owner ((a message that at least one player is needed)); one side enough, no sight test. Each click on a home-system object adds another copy (same planet several times). Ours requires two sides, refuses "Nobody on the field can see an enemy", refuses duplicate planets (src/game/simulator.cpp:256, simulator.cpp:126, combat_logic.cpp:323). Spec 06 §1.10.4 partially.
15. DIFFERENT L — Turning Auto off in a simulation gives side 1 to the player and every other side to the computer regardless of Computer Control. Real game: each empire gets back its own computer flag. Ours restores setup's own choice (combat_tactical.cpp:305). Spec 04 §4/§17.
16. COSMETIC L — After Resolve Combat confirm, all four buttons dim (Options incl), Auto shows pressed. Ours Options live, Auto up.
