# Diplomacy & reports audit (analyst findings, plain language).

1. MISSING M — "Want a gift"/"Want a tribute" carry a package: choosing either opens Select Package on the recipient's side ("Any" allowed); wanted items stored with message; empty package can't be sent. Edit Package lit for exactly Give Gift, Offer Tribute, Want a gift, Want a tribute. Ours: messageNeeds() gives no package (screens/empire_logic.cpp:84); AI payUp builds the gift from msg.request (game/ai_diplomacy.cpp ~704) so human requests are always empty/refused. Spec 06 §4.2, spec 05 §3.4 (§7.4 assumes it).
2. DIFFERENT M — Answering from Empires portrait: Communicate opened from a portrait looks at the newest political message from that empire inside the reply window (last 2 turns; simultaneous game: last 1 turn when sender's number is lower) and adds reply types: Accept/Refuse/Counter Treaty after Propose or Counter Treaty; Accept/Refuse/Counter Trade after trade; Accept/Refuse Gift after gift; Accept/Refuse Tribute after tribute; Accept/Refuse Demand after any demand. Ours: portrait opens compose mode only (empires.cpp:269-271, communicate.cpp:216); answers only via Log Send Reply (keep). Spec 06 §4.2, §1.5.
3. DIFFERENT M — Propose/Counter Treaty picker: Non-Intercourse, Non-Aggression, Subjugation, Protectorate, Trade, Trade and Research, Military Alliance, Partnership. No War, no None; current treaty stays listed (so war can't end in "None"; peace = NI or better). Package Treaty tab: every treaty except "no contact", None, and the current one; War included. Ours: proposableTreaties() lists None, omits current and War; firstProposable() suggests None at war (communicate.cpp:157); Treaty tab same list. Spec 05 §3.2/§3.4.
4. MISSING M — Subjugated empire (holds Subjugation as subordinate side; Protectorate doesn't count): no Propose Treaty in its list; Propose/Counter refused a message that subjugated empires cannot propose treaties; Accept Treaty refused a message that subjugated empires cannot accept treaties; includes with its master. Break Treaty and Declare War stay. Client-side check. Ours: only setTreaty blocks third-empire treaties (diplomacy.cpp ~299). Spec 05 §3.2, replaces [I] choice.
5. DIFFERENT M — Treaty Grid: player first then every known empire. Cell A–B filled only when (A or B is us, or we hold Non-Aggression or better with A or with B) AND A–B hold a real treaty; None/no-contact cells blank; legend omits None. Subjugation/Protectorate cells carry role mark "(S, D)" or "(D, S)" in (row,column) order. Codes: War, NI, NA, Sub, Pro, TA, TR, MA, P. Ours: visibility via allied() (MA or better) in treatyVisibleTo (empire_logic.cpp) and diplomacy::treatyVisible; "--" for None, "??" for hidden, no role mark, codes WR/SB/PR/PS. "AI State" button = debug only, no gap. Spec 05 §3.2, spec 06 §1.5.
6. DIFFERENT M — Comparisons graph plots only rows in player's statistics file: an empire has a row only for turns it was visible then (gaps); list holds every empire with >=1 row (dead / no longer visible incl). Ours filters by current visibility and plots whole history + live turn (empires.cpp:760-820, empire_logic.cpp:486). Spec 05 §5 already says it; code gap.
7. DIFFERENT L–M — Message types offered: Surrender and Demand your surrender only with Allow Surrender on (ours always; Surrender with option off does nothing). Grant independence never listed and has no effect in processing (ours offers it and abandons the colony, inferred; spec [M] text contradicted). Break Treaty needs NA or better (ours also under NI). Propose Trade and every request offered even at war (ours hides at war). Want gift/tribute don't depend on gifts option (ours hides when gifts off). Demands behind a "Demand / Request / Warn" entry switching to 16 subtypes (ours flat; cosmetic). Keep our Declare War confirmation. Spec 06 §4.2, spec 05 §3.4.
8. DIFFERENT L — Trade needs items on both sides: Propose/Counter Trade invalid if either side empty. Counter starts from received packages swapped; if give side then holds "Any" items -> warning a warning that a trade offer cannot contain unspecified "Any" items, player must replace them. Ours blocks only both-empty, silently drops Any from counter's give side (communicate.cpp:402,716). Spec 06 §4.2.
9. DIFFERENT L–M — Default message text: on picking a type, text box filled with a random line from the player's own race _AI_Speech pool "Send <Type>"; Accept/Refuse Demand uses "Response Friend|Enemy YES|NO <Demand>" where Friend = NA or better with recipient. Use UI-local random, not GameState::rng. Ours: fixed English from defaultMessageText(). Spec 06 §4.2.
10.
